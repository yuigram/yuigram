# Эксплуатация: среды выполнения, миграция, безопасность, проверка

[Оглавление](README.md) · назад: [Воркеры, стриминг, ошибки, тесты](advanced.md)

## Среды выполнения

Основная платформа — Node.js 22 или новее: на ней работает всё. Остальное проверено матрицей
сред выполнения против локального датацентра-заменителя, который говорит на настоящем
протоколе MTProto, и против поддельного сервера Bot API. «Запущено» в таблице означает, что
проверка выполнялась в этой среде; «ожидается» — что код не делает ничего, чего там нет, но
отдельно не запускался.

| Возможность | Node 22+ | Bun | Deno | Workers / Edge | Браузер |
| --- | --- | --- | --- | --- | --- |
| Bot API: вызов через `fetch` и его отмена | запущено | запущено | запущено | запущено | ожидается¹ |
| Bot API: webhook на Fetch API | запущено | запущено | запущено | запущено | — |
| Bot API: long polling | запущено | ожидается | ожидается | —² | ожидается¹ |
| Bot API: файлы по пути на диске | запущено | ожидается | ожидается³ | нет | нет |
| Хранилища `memory()`, `file()` | запущено | запущено | запущено³ | только `memory()` | `web()` — запущено |
| `@yuigram/sqlite` | запущено | запущено | запущено | нет | нет |
| MTProto: аккаунт целиком | запущено | запущено | запущено | запущено⁴ | запущено |

¹ Bot API не отдаёт заголовки CORS, поэтому страница в браузере не может обращаться к нему
напрямую: код работает, запрос отклоняет браузер.
² Long polling нужен процесс, который живёт дольше запроса; на edge-платформах используют
webhook.
³ Deno нужны `--allow-read` и `--allow-write` для каталога.
⁴ В workerd локально, через Miniflare; не в сети Cloudflare и не на Vercel Edge.

Проверенные версии: Bun 1.4.2, Deno 2.9.6. Полная таблица и то, что из неё выведено, а не
запущено, — в [runtimes.md](../runtimes.md).

**С самим Telegram запускался только пример 20, вручную,** на Node.js в Windows: вход в аккаунт,
статусы, бот. Проверки выше используют поддельные транспорты и датацентр-заменитель. Порядок
проверки на живом Telegram подготовлен, но не выполнялся — он описан
[ниже](#проверка-на-живом-telegram).

Бандл программы, которая использует только Bot API, не содержит ни одного модуля MTProto, а
каждый подпуть `yuigram/…` загружается, только когда его импортируют.

## Миграция

Опубликованная версия `0.1.0` — это клиент Bot API. Следующий выпуск меняет его поверхность и
добавляет MTProto; полный список переименований и причины — в [migration.md](../migration.md).
Главное:

- Обработчик получает контекст, который доказала его регистрация, а не самый слабый случай среди
  всех видов обновлений. Именованные регистрации — `onMessage`, `onChatMemberJoined` и другие.
- Параметр типа клиента несёт то, что *добавляют* плагины (`Bot<SessionFlavor<Cart>>`), а не весь
  контекст.
- MTProto добавлен, а не заменяет что-то: боту, который его не использует, мигрировать не нужно,
  и его бандл не растёт.

Изменения, сделанные в этом цикле уже после первых описаний `0.2` (каждое записано в
`.changeset/`):

| Изменение | Что сделать |
| --- | --- |
| `bootstrapAt({ dc, host, port })` вместо литерала `DcConfiguration` | Заменить литерал вызовом; старый литерал по-прежнему работает. |
| `new App()` без аргумента типа описывает события как `BaseContext` | Ничего, если клиенты из Yuigram; для своего клиента — `new App<MyEvent>()`. |
| Ключ `session()` видит `chat` и `sender` и может вернуть `bigint` | Ничего; `createSession` с явным типом больше не нужен для этих случаев. |
| Фильтр бота на аккаунте — ошибка компиляции | Заменить на фильтр из `yuigram/account-filters`, например `f.chat('user')` вместо `f.chat.private`. |
| `when(filter, middleware)` сужает контекст по фильтру | Убрать приведения типов в таком middleware. |
| `schemaInfo.botApi` сообщает версию, из которой сгенерирована поверхность | Ничего. |

## Безопасность

Yuigram работает с учётными данными, и большинство реальных утечек — не взлом шифрования, а
токен в агрегаторе логов или сессия в репозитории.

| Что | Чем опасно | Как обращаться |
| --- | --- | --- |
| Токен бота | управление ботом | только из окружения или менеджера секретов; не в коде и не в логах |
| `apiHash` | учётные данные приложения | так же; в строку сессии он не входит |
| Каталог сессии, строка `exportSession()` | **это вошедший аккаунт** | не в репозиторий, не в логи, не в сообщения; при утечке — отозвать сессию в Telegram |
| Адрес `getFileUrl()` | содержит токен бота | не писать в логи и не передавать третьим лицам |
| Код входа, пароль 2FA | вход в аккаунт | не хранить; вводить вручную |

Что делает фреймворк:

- **Логи редактируются структурно** и это нельзя отключить: токены, `api_hash`, ключи
  авторизации, строки сессий, коды входа, пароли и `access_hash` не попадают в лог ни на каком
  уровне, включая `debug`.
- **Файлы сессии** создаются с правами только для владельца, а каталог, доступный кому-то ещё,
  вызывает предупреждение. Шифрование на диске — по желанию, через `encrypted(store, secret)`
  (AES-256-GCM, ключ выводится через scrypt).
- **Одна область — один запуск аккаунта.** Второй запуск аккаунта с тем же именем отклоняется
  (`StorageOwnershipError`) в пределах процесса и браузерного источника, а между процессами — над
  SQLite и Redis, где аренда проверяется атомарно при каждой записи. Над обычным каталогом между
  процессами это не блокировка: отклоняется только запуск, начавшийся после записи о владельце.
- **Проверки протокола не отключаются.** Ключ датацентра сверяется по отпечатку, параметры
  обмена ключами проверяются полностью, TLS для Bot API проверяется всегда.
- **Узлы доставки (CDN) выключены по умолчанию**; включённые, они получают только запросы
  диапазонов файла, а полученные байты сверяются с опубликованными хешами.
- **Вебхук сравнивает `secretToken`** за постоянное время и отбрасывает повторную доставку.
- **Имя файла из Telegram выбрал отправитель**, поэтому оно никогда не превращается в путь на
  диске.

Аккаунт действует от имени человека. Telegram блокирует аккаунты, которые используют для
флуда, спама и накрутки, и блокировка касается аккаунта, а не приложения. Прежде чем входить в
настоящий аккаунт, стоит прочитать начало [mtproto.md](../mtproto.md).

Модель угроз целиком — [security.md](../security.md). Об уязвимостях сообщайте приватно, как
описано в [SECURITY.md](../../SECURITY.md).

## Проверка на живом Telegram

Всё остальное в репозитории проверяется без Telegram. Подтвердить, что сам Telegram согласен,
может только проверка на живой сети; для неё есть пакет `tools/live` и пошаговая инструкция
[live-verification.md](../live-verification.md). **Она подготовлена, но ещё не выполнялась;** что
показали ручные запуски примера 20, записано в конце того же документа.

Основные правила:

- **Ничего не запускается само.** Каждый вид изменений требует своей переменной:
  `YUIGRAM_LIVE_ALLOW_LOGIN=1` для входа, `YUIGRAM_LIVE_ALLOW_SESSION=1` для проверок от имени
  аккаунта, `YUIGRAM_LIVE_ALLOW_WRITES=1` для отправки, `YUIGRAM_LIVE_ALLOW_LOGOUT=1` для выхода,
  а `YUIGRAM_LIVE_CHECKS` перечисляет проверки поимённо — варианта «всё» нет.
- **Предпочтительна тестовая среда Telegram** (`YUIGRAM_LIVE_TEST_NETWORK=1`): свои аккаунты,
  чаты и боты, ничего не пересекается с боевой сетью. Тестовые номера вида `+99966 X YYYY` не
  требуют SIM-карты.
- **Нужен тестовый аккаунт, а не собственный**: каждый шаг действует от его имени.
- **Секреты — в файле вне репозитория с правами только для владельца**, загруженном в оболочку
  перед запуском. Не в истории команд, не в задачах и никогда не в переписке. Код и пароль не
  передаются переменными: `login` спрашивает их в терминале, пароль — без эха.

```bash
pnpm --filter @yuigram/live live --list
```

Эта команда только перечисляет проверки и переменные и ни к чему не подключается. Порядок
шагов, команды и ожидаемый вывод — в [live-verification.md](../live-verification.md) §4.

## Разработка

```bash
pnpm install
pnpm verify      # линтер, типы, инварианты архитектуры, тесты, бюджет деклараций
pnpm smoke       # упаковать пакеты, установить и использовать как приложение
pnpm bench       # бюджеты запуска, бандлов и диспетчеризации
```

Матрица сред выполнения и тесты Redis требуют внешних программ; как их запустить — в
[CONTRIBUTING.md](../../CONTRIBUTING.md).
